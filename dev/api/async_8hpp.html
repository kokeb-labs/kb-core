Detailed Description

The asynchronous bus contract (ADR-0016): start a transfer, poll it without waiting until it completes or its deadline passes, cancel it; I2cAsync and SpiAsync, and AsyncFromSync, which serves the contract from a synchronous port.

Member Meaning
kb::Status Start...(..., kb::utils::Deadline deadline) noexcept Starts one transfer and returns at once: Ok (started), Busy (one is in flight), InvalidArgument (bad spans or address), Timeout (the deadline has passed), NotReady
AsyncPoll Poll(kb::Instant now) noexcept Never waits: Idle, Pending, or Done with the outcome, reported exactly once
kb::Status Cancel() noexcept Ends the transfer in flight within a bounded time; afterwards nothing touches the buffers and Poll() reports Idle
static constexpr bool kNonBlocking True when Start() and Poll() never wait for the bus (a native port); false for AsyncFromSync

Rules every port keeps:

  • One transfer in flight per object; the caller's spans stay valid until Done is reported or Cancel() returns.
  • A transfer that has not completed by its deadline completes as Timeout; a completion that arrives after the deadline is Timeout too (late data is never reported as Ok).
  • Cancel() racing a completion: whichever wins, Cancel() returns Ok, the completion is dropped, and the next Poll() is Idle.
  • Completion is signalled from the ISR by the port (an event flag of the owner task, or nothing: the owner polls once per pass). Poll() itself is callable from one task only, never an ISR.

The synchronous contracts (I2cBus, SpiDevice) are unchanged; an async port is also a sync port, for start-up and slow paths.

Detailed Description

kb::rtos::Mutex and kb::rtos::RecursiveMutex with a bounded try-lock, and the RAII LockGuard and RecursiveLockGuard that hold them for one scope.

A mutex is constructed inert (constexpr, no RTOS call) and becomes usable with Create(), called after the scheduler runs. Every lock is bounded: TryLockFor(timeout) waits at most timeout (at least that long when it fails) and says whether it got the lock. Locking before Create() fails.

kb::rtos::Mutex bus_lock{};
if (!bus_lock.Create().IsOk()) { ... }
{
kb::rtos::LockGuard guard{bus_lock, kb::Milliseconds{5U}};
if (!guard.OwnsLock()) { return kb::Status::Busy; }
... // exclusive access; unlocked at the end of the scope
}
kb::Milliseconds
A duration in milliseconds (32-bit count: up to about 49.7 days).

A RecursiveMutex may be taken again by its holder (each take needs its own unlock); prefer Mutex, whose second take by the holder fails instead of hiding a re-entry.

Both priority-inherit where the RTOS has it (FreeRTOS mutexes, ThreadX TX_INHERIT). Not callable from an interrupt handler.

# tmc5160 handler

TMC5160 and TMC5160A stepper motion controllers and drivers, on SPI or on the single-wire UART, through
`kb::handlers::tmc5160::Handler<Bus, kControlPins>` (`kb/handlers/bindings/tmc5160.hpp`, driver `driver-tmc5160` at
the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `status` (the driver's `ReadSnapshot()`: GSTAT, DRV_STATUS, RAMP_STAT, XACTUAL, VACTUAL, TSTEP, MSCNT), `enabled`, `fault` |
| Command | `Enable(io, timeout)`, `Disable(io, timeout)` | The driver stage on or off (TOFF, and DRV_ENN with control pins) |
| Command | `MoveTo(io, position, timeout)` | Position mode with the configured ramp |
| Command | `RunVelocity(io, velocity, timeout)` | Velocity mode, signed |
| Command | `Stop(io, kind, timeout)` | Ramp, immediate, hold-target or emergency stop |
| Command | `SetCurrent(io, run_ma, hold_ma, timeout)` | Run and hold current; returns the run current the registers give |
| Command | `ReadPosition(io, timeout)` | XACTUAL, read now |
| Command | `ServiceEvents(io, timeout)` | Read and clear the events after a DIAG0 interrupt |
| Command | `Command{Op::...}` with `Request()` | Move by, hold, VMAX, home position, velocity, position reached, clear faults, a register, release a stall |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus.

The bus type picks the transport: a `kb::iface::SpiDevice` gives the SPI datagram link, a `kb::iface::UartPort` the
UART link (the port must not return the echo of its own bytes). With `kControlPins = false` (the default) the driver
gets no pin hooks: it switches the bridge with TOFF only, so DRV_ENN must be tied low. With `kControlPins = true` the
HAL gives DRV_ENN, DCEN and DCIN outputs and DIAG0, DIAG1 and DCO inputs in `Config::pins` (polarity in
`OutputPin`/`InputPin`; DRV_ENN is usually `active_low`); a pin the board does not wire then fails its hook.

## Thread model

`kRequiresOwner = false`. Motion commands are sporadic and the ramp runs in the chip, so a guarded bus
(`BusDomain<Bus, ThreadModel::Guarded>` with `Guarded<Handler>`) is the usual choice; on an owner bus the owner task
reads the status every `sample_period` and other tasks read `Latest()`.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: bus up, quiesce, IOIN version and SD_MODE strap, GSTAT cleared, every register written | `Config::start_deadline` |

The chip has no reset pin, and the driver drives DRV_ENN itself when it has the pin, so there is no `Power` or
`HostReset` stage. On a failure the report names stage 0 with the driver's error in `detail`; the next
`EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `UnexpectedReset`, `NotInitialized` | `NotReady` | Faulted at once (the chip lost its registers) |
| `Bus` | `BusError` | Counts toward `fault_after` |
| `DeviceIdMismatch` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `InvalidArgument`, `Refused` | `InvalidArgument` | Refused: recorded as the last error, not counted against the chip (a caller's mistake) |
| `LimitExceeded` | `OutOfRange` | Counts toward `fault_after` |
| `Crc` | `CrcMismatch` | Counts toward `fault_after` (UART) |
| `DeviceFault`, `VerifyFailed`, `ModeMismatch` | `Fault` | Counts toward `fault_after` |
| `Timeout`, `Busy`, `Unsupported` | the same name | Counts toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (the driver stage off), then the start-up again, which writes the
whole configuration.

## Example

```cpp
using Dev = board::Spi1Axis0;                                     // a kb::iface::SpiDevice
using Axis = kb::handlers::tmc5160::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Guarded> spi1{dev};
kb::handlers::Guarded<Axis, decltype(spi1)> axis{spi1, dev, timing, config};

static_cast<void>(spi1.Create());
static_cast<void>(axis.Create());
if (axis.EnsureStarted(kb::Milliseconds{100U}).IsOk()) {
  static_cast<void>(kb::handlers::tmc5160::Enable(axis, kb::Milliseconds{10U}));
  static_cast<void>(kb::handlers::tmc5160::MoveTo(axis, 51200, kb::Milliseconds{10U}));
  const kb::Result<int32_t> at = kb::handlers::tmc5160::ReadPosition(axis, kb::Milliseconds{10U});
}
```

Tests: `tests/integration/tmc5160/` (the driver's chip model behind a `kb::iface::SpiDevice` and a
`kb::iface::UartPort`, control pins, both thread models).

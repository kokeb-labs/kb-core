# mcp9700 handler

MCP9700, MCP9700A, MCP9700B, MCP9701 and MCP9701A linear active thermistors (analog output), through
`kb::handlers::mcp9700::Handler<Adc>` (`kb/handlers/bindings/mcp9700.hpp`, driver `driver-mcp9700` at the pin in
`components/drivers/drivers.lock.yml`). The sensor is read through one `kb::iface::AdcChannel` in calibrated millivolts.

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `temperature_mc` (after the calibration offset), `output_mv` (mean sensor output), `spread_mv` (largest minus smallest conversion of the reading) |
| Read | `ReadTemperature(io, timeout)` | A fresh averaged, validated reading (a sample, also published to `Latest()`) |
| Command | `ReadRawMv(io, timeout)` | One conversion at the ADC pin, no plausibility check (bring-up, wiring) |
| Command | `Command{Op::ReadMeasurement}` with `Request()` | A full reading as the reply, without publishing it |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus. The kb ADC channel is the
sensor's channel, so `Config::chip.channel` is not used. The optional supply pin is `Config::enable` (absent: the
sensor sits on the rail and is always powered).

## Thread model

`kRequiresOwner = false`. The sensor needs no servicing and a reading takes a few conversions, so a guarded
channel (`BusDomain<Adc, ThreadModel::Guarded>` with `Guarded<Handler>`) is the default; on an owner channel the
owner task samples every `sample_period` and other tasks read `Latest()`.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: configuration check, supply pin on, settle wait, first reading checked for a plausible, stable output | `Config::start_deadline` |

The driver drives the supply pin itself (`GpioSet`), so there is no `Power` stage. A sensor that is absent,
unpowered, shorted or on the wrong channel fails stage 0 with `Fault` and `DeviceIdMismatch` in `detail`; the next
`EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `NotInitialized` | `NotReady` | Faulted at once |
| `Bus` (a conversion or the supply pin failed) | `BusError` | Counts toward `fault_after` |
| `OutputLow`, `OutputHigh`, `Saturated` | `OutOfRange` | Counts toward `fault_after` |
| `DeviceIdMismatch`, `Unstable`, `DeviceFault` | `Fault` | Counts toward `fault_after`; at start-up the start fails |
| `InvalidArgument`, `Unsupported`, `Timeout`, `Crc`, `Busy` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (supply off), then the start-up again.

## Example

```cpp
using Adc = board::TempAdc;                                       // a kb::iface::AdcChannel
using Io = kb::handlers::mcp9700::Handler<Adc>;
kb::handlers::BusDomain<Adc, kb::handlers::ThreadModel::Guarded> adc0{adc};
kb::handlers::Guarded<Io, decltype(adc0)> temp{adc0, adc, timing, config};

static_cast<void>(adc0.Create());
static_cast<void>(temp.Create());
if (temp.EnsureStarted(kb::Milliseconds{50U}).IsOk()) {
  const kb::Result<int32_t> mc = kb::handlers::mcp9700::ReadTemperature(temp, kb::Milliseconds{20U});
}
```

Tests: `tests/integration/mcp9700/` (the driver's sensor and ADC model behind a `kb::iface::AdcChannel`, its supply
pin behind a host GPIO fake, both thread models).

# max22200 handler

MAX22200 and MAX22200A eight-channel solenoid and valve drivers on SPI, through
`kb::handlers::max22200::Handler<Dev>` (`kb/handlers/bindings/max22200.hpp`, driver `driver-max22200` at
the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `status` (STATUS: ONCH, flags, ACTIVE), `latched` (the driver's fault latch), `commanded` (ONCH as last written) |
| Command | `SetChannelsOn(io, mask, timeout)` | Every channel at once: bit n of `mask` switches channel n on |
| Command | `SetChannel(io, channel, on, timeout)` | One channel, the others as the driver last wrote them |
| Command | `AllOff(io, timeout)` | Every channel off, read back |
| Command | `ReadFaults(io, timeout)` | The per-channel FAULT flags, without clearing |
| Command | `ClearFaults(io, timeout)` | Clears every FAULT flag; returns the flags as they were |
| Command | `ReadFaultPin(io, timeout)` | The FAULT pin: true while an unmasked fault is present |
| Command | `Command{Op::...}` with `Request()` | Full-bridge state, HOLD code, pair mode, ONCH and STATUS reads, latch clear, raw register |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus.

**Pins.** `Config::outputs` holds ENABLE (`kPinEnable`, active high) and CMD (`kPinCmd`, active high,
required); `Config::inputs` holds FAULT (`kPinFault`, open drain: wire it active low). A board that ties
ENABLE high leaves `kPinEnable` absent: the port then reports ENABLE as driven, as the driver expects. The
port's first bring-up drives CMD high and ENABLE low (their idle levels) before the first transfer.

**Safety.** The handler only reports. A Faulted health record does not switch any output: what the outputs
do on a chip or bus fault is the driver's and the chip's business, and the driver sends nothing more after a
reset it sees. `Recover()` and `Stop()` call `Deinitialize()`, which writes every channel off and drives
ENABLE low before the plan runs again, and every start ends with every channel off. A safety layer must reach
its safe state without any handler call succeeding (ADR-0011).

The port's `DelayUs` goes through the hook timing: a spin on the HAL's busy-wait below 1 ms, a
`kb::rtos::SleepFor` (at least the time asked) from 1 ms.

## Thread model

`kRequiresOwner = false`. Valves are switched by commands from a control task and supervised now and then,
so a guarded bus is the usual choice and `Sample()` reads STATUS on demand. On an owner bus the owner task
reads STATUS every `sample_period` (a reset shows there as `DeviceReset`) and switching commands go through
the request queue.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: CMD high, ENABLE high and tEN, the Figure 6 procedure with the wake poll (`chip.wake_timeout_us`), every register written and read back, start-up faults read and cleared; every channel off | `Config::start_deadline` |

The driver drives ENABLE itself, so there is no `Power` stage. On a failure the report names stage 0 with
the driver's error in `detail` (ENABLE is low again, except after a wake timeout, with every channel off);
the next `EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `DeviceReset`, `NotInitialized` | `NotReady` | Faulted at once (ACTIVE read 0: a power-on reset cleared every register) |
| `Undervoltage` | `NotReady` | Counts toward `fault_after`; at start-up VM was still low at the wake deadline |
| `Bus`, `Pin`, `CommunicationError` | `BusError` | Counts toward `fault_after` (a transfer, a control pin, or a miscounted write) |
| `NoDevice` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `ChannelsActive` | `Busy` | Counts toward `fault_after`; nothing sent, switch the channels off first |
| `DeviceIdMismatch`, `WriteMismatch`, `Uncertain` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `Timeout`, `Unsupported` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |
| `Crc`, `Busy`, `DeviceFault` | `CrcMismatch`, `Busy`, `Fault` | Not returned by the driver (faults are data) |

Recovery is the generic plan: `Deinitialize()` (every channel off, ENABLE low), then the start-up again.

## Example

```cpp
using Dev = board::Spi3Valves;                                    // a kb::iface::SpiDevice, mode 0
using Valves = kb::handlers::max22200::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Guarded> spi3{dev};
kb::handlers::max22200::Config config{};
config.chip.loaded_channels = 0x0FU;                              // board fact: valves on channels 0 to 3
config.outputs[kb::handlers::max22200::kPinCmd].pin.emplace(cmd_pin);
config.outputs[kb::handlers::max22200::kPinEnable].pin.emplace(enable_pin);
kb::handlers::Guarded<Valves, decltype(spi3)> valves{spi3, dev, timing, config};

static_cast<void>(spi3.Create());
static_cast<void>(valves.Create());
if (valves.EnsureStarted(kb::Milliseconds{200U}).IsOk()) {
  static_cast<void>(kb::handlers::max22200::SetChannelsOn(valves, 0x05U, kb::Milliseconds{5U}));
}
```

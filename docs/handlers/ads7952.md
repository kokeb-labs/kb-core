# ads7952 handler

ADS7950, ADS7951, ADS7952 and ADS7953 4- to 16-channel, 12-bit SPI SAR ADCs, through
`kb::handlers::ads7952::Handler<Dev>` (`kb/handlers/bindings/ads7952.hpp`, driver `driver-ads7952` at the pin in
`components/drivers/drivers.lock.yml`). The chip is one `kb::iface::SpiDevice` (its chip select), one 16-bit frame per
transfer.

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | One Auto-1 scan: `code[16]` (channel n at index n), `mask` (the channels scanned), `range` |
| Command | `ReadChannel(io, ch, timeout)` | The code of one channel, converted now (Manual mode) |
| Command | `ScanAuto1(io, timeout)` | One Auto-1 pass now, as a `Snapshot` |
| Command | `SetRange(io, range, timeout)` | 0 to VREF or 0 to 2 x VREF |
| Command | `SetGpioOutputs(io, levels, timeout, verify)` / `ReadGpio(io, timeout)` | The GPIO pins |
| Command | `CheckScale(io, timeout)` | The scale monitor's code, checked against its window |
| Command | `Command{Op::...}` with `Request()` | `ScanAuto2`, `SetAuto1Channels`, `SetAuto2LastChannel`, `SetAlarmThresholds` |

Codes convert to microvolts with `ads7952::CodeToMicrovolts(code, range, vref_mv)`.

## Thread model

`kRequiresOwner = false`; either model works, and the choice depends on use:

- **Owner** (the usual choice for control loops and monitoring): the owner task scans the Auto-1 sequence every
  `sample_period` and publishes it, so any task reads the newest scan lock-free with `Latest()` (sequence and age
  included), and on-demand reads go through the owner's queue.
- **Guarded**: a task reads single channels on demand (`ReadChannel()`), for slow or occasional measurements on a
  bus shared with other slow devices.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: register reset, power-up wait, every program register written, channel-address identity check, optional scale monitor | `Config::start_deadline` |

The chip has no reset or enable pin (the driver resets it by command), so there is no `Power` or `HostReset`
stage. Every reply 0xFFFF fails stage 0 with `NoDevice`; replies without the channel addresses with `Fault`
(`DeviceIdMismatch`).

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `DeviceReset`, `NotInitialized` | `NotReady` | Faulted at once (a brown-out reset the registers) |
| `Bus`, `ChannelMismatch`, `SequenceMismatch` | `BusError` | Counts toward `fault_after` |
| `NoDevice` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `DeviceIdMismatch`, `WriteMismatch`, `RangeMismatch`, `ScaleMismatch`, `DeviceFault` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `Unsupported`, `Timeout`, `Crc`, `Busy` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (power-down frame), then the start-up again, which programs the
chip in full.

## Example

```cpp
using Dev = board::AdcCs;                                         // a kb::iface::SpiDevice
using Io = kb::handlers::ads7952::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Owner> spi1{dev};
kb::handlers::OwnerAccess<Io, decltype(spi1)> adc{spi1, dev, timing, config};

static_cast<void>(adc.Create());
// The owner task: spi1.Service(kb::rtos::Now(), adc) every step.
if (adc.EnsureStarted(kb::Milliseconds{20U}).IsOk()) {
  const auto scan = adc.Latest();                                  // the newest Auto-1 scan
  const kb::Result<uint16_t> ch3 = kb::handlers::ads7952::ReadChannel(adc, 3U, kb::Milliseconds{5U});
}
```

Tests: `tests/integration/ads7952/` (the driver's chip model behind a `kb::iface::SpiDevice`, both thread models,
the owner one sampling Auto-1 scans).

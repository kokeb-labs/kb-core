# tmc9660 handler

TMC9660 servo controllers and gate drivers, on SPI or UART, in parameter, register or bootloader mode, through
`kb::handlers::tmc9660::Handler<Bus, kControlPins>` (`kb/handlers/bindings/tmc9660.hpp`, driver `driver-tmc9660` at
the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `mode`, `last_status`; in parameter mode also `velocity`, `position` and `general_errors` (after a good `Service()`) |
| Command | `EnableDrive(io, commutation_mode, timeout)` | Energise the gate driver in parameter mode, after the driver's guards |
| Command | `DisableDrive(io, timeout)` | Switch the gate driver off (never refused) |
| Command | `SetTargetVelocity(io, velocity, timeout)` | TARGET_VELOCITY |
| Command | `SetTargetPosition(io, position, timeout)` | TARGET_POSITION |
| Command | `GetParam(io, param, timeout)` | An axis parameter, read now |
| Command | `SetParam(io, param, value, timeout)` | An axis parameter, checked against the driver's table |
| Command | `Command{Op::...}` with `Request()` | Motor stop, target torque, clear flags, register read and write (register mode), chip ID, `Service()` |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus. A call that belongs to another
mode returns `Unsupported` with `WrongMode` in the detail and sends nothing.

The bus type picks the transport: a `kb::iface::SpiDevice` gives the SPI link, a `kb::iface::UartPort` the UART link
(the port must not return the echo of its own bytes; a driver exchange with no bytes to send only drains the line).
With `kControlPins = false` (the default) the driver gets no pin hooks: no hardware reset, DRV_EN wired high, and the
stop is made with parameters. With `kControlPins = true` the HAL gives RSTN, DRV_EN and WAKE outputs and the FAULTN
input in `Config::pins` (RSTN and FAULTN are usually `active_low`); DRV_EN must then be wired, because a missing
output fails its hook (the driver still sends every stop frame and reports `Bus`).

## Thread model

`kRequiresOwner = false`. Set points and parameter access are sporadic and the control loops run in the chip, so a
guarded bus is the usual choice. On an owner bus the owner task runs `Service()` (FAULTN, the error flags and the
heartbeat) and the parameter reads every `sample_period`; other tasks read `Latest()`.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: bus up, RSTN pulse when `chip.hardware_reset` (the driver drives the pin), chip ID in `chip.mode` | `Config::start_deadline` (above `chip.boot_timeout_ms`) |

The driver drives RSTN itself, so there is no `HostReset` stage. On a failure the report names stage 0 with the
driver's error in `detail`; the next `EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `UnexpectedReset`, `NotInitialized` | `NotReady` | Faulted at once (the chip restarted) |
| `Bus` | `BusError` | Counts toward `fault_after` |
| `DeviceIdMismatch` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `InvalidArgument`, `Refused` | `InvalidArgument` | Refused: recorded as the last error, not counted against the chip (a caller's mistake) |
| `Crc`, `BadReply` | `CrcMismatch` | Counts toward `fault_after` |
| `Nack` | `Nack` | Counts toward `fault_after` |
| `Unsupported`, `WrongMode` | `Unsupported` | Counts toward `fault_after` |
| `DeviceFault`, `VerifyFailed` | `Fault` | Counts toward `fault_after` |
| `Timeout`, `Busy` | the same name | Counts toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (the gate driver off, also after a reported reset), then the start-up
again, which adopts the chip in `chip.mode`.

## Example

```cpp
using Dev = board::Spi2Servo;                                     // a kb::iface::SpiDevice
using Servo = kb::handlers::tmc9660::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Guarded> spi2{dev};
kb::handlers::Guarded<Servo, decltype(spi2)> servo{spi2, dev, timing, config};

static_cast<void>(spi2.Create());
static_cast<void>(servo.Create());
if (servo.EnsureStarted(kb::Milliseconds{600U}).IsOk()) {
  static_cast<void>(kb::handlers::tmc9660::EnableDrive(servo, 2U, kb::Milliseconds{50U}));
  static_cast<void>(kb::handlers::tmc9660::SetTargetVelocity(servo, 1000, kb::Milliseconds{20U}));
}
```

Tests: `tests/integration/tmc9660/` (the driver's chip model behind a `kb::iface::SpiDevice` and a
`kb::iface::UartPort`, parameter and register mode, control pins, both thread models).

# pca9685 handler

PCA9685 16-channel, 12-bit I2C PWM / LED controller, through `kb::handlers::pca9685::Handler<Bus, kOutputEnable>`
(`kb/handlers/bindings/pca9685.hpp`, driver `driver-pca9685` at the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | After a reset check: `frequency_hz` (of the prescaler), `uncertain` (channels whose last write failed), `may_be_asleep` |
| Command | `SetDuty(io, ch, duty, timeout, phase)` | Channel `ch` to `duty` of 4096 (0 off, 4096 full on) starting at `phase` |
| Command | `SetPulseWidthUs(io, ch, width_us, timeout)` | A servo-style pulse; returns the width set in nanoseconds |
| Command | `SetChannelOff(io, ch, timeout)` / `SetAllOff(io, timeout)` | Switch-offs |
| Command | `SetPwmFrequency(io, hz, timeout)` | The prescaler (the chip sleeps for the change) |
| Command | `DisableOutputs(io, timeout)` / `EnableOutputs(io, timeout)` | OE high or low (needs `kOutputEnable`) |
| Command | `Command{Op::...}` with `Request()` | `SetPwm`, `SetFullOn`, `SetChannelsOff`, `Sleep`, `Wake`, `ReadChannel`, `CheckForReset` |

`kOutputEnable` (default `false`) says whether the board wires OE to the MCU. Without it the port has no `GpioSet`
hook and `DisableOutputs()` / `EnableOutputs()` return `Unsupported`, never a success they cannot deliver. With it,
`Config::output_enable` names the pin; OE is active low (asserted = outputs enabled = pin low), which is the
default polarity.

## Thread model

`kRequiresOwner = false`. Set-points are written now and then, often from several tasks, so a guarded bus is the
usual choice. On an owner bus the periodic sample is a reset check (`CheckForReset()`), so a chip that lost its
registers faults within one `sample_period`.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: every output off, clock and prescaler, identity by read-back (no ID register), wake with the oscillator wait, OE asserted | `Config::start_deadline` |

The chip has no reset pin, and the driver drives OE itself, so there is no `Power` or `HostReset` stage. No
acknowledge at the address fails stage 0 with `NoDevice`; a part that does not keep its registers with `Fault`
(`DeviceIdMismatch`).

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `DeviceReset`, `NotInitialized` | `NotReady` | Faulted at once (the chip lost its registers) |
| `Asleep` | `NotReady` | Counts toward `fault_after` (written, but the outputs follow only after `Wake()`) |
| `Bus`, `InvalidReply` | `BusError` | Counts toward `fault_after` |
| `NoDevice` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `DeviceIdMismatch`, `WriteMismatch`, `StateUnknown`, `ExternalClockLatched`, `DeviceFault` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `Unsupported`, `Timeout`, `Crc`, `Busy` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (OE high, every channel off, sleep), then the start-up again.

## Example

```cpp
using Bus = board::I2c1;                                          // a kb::iface::I2cBus
using Io = kb::handlers::pca9685::Handler<Bus, true>;             // OE wired to the MCU
kb::handlers::BusDomain<Bus, kb::handlers::ThreadModel::Guarded> i2c1{bus};
kb::handlers::Guarded<Io, decltype(i2c1)> pwm{i2c1, bus, timing, config};

static_cast<void>(i2c1.Create());
static_cast<void>(pwm.Create());
if (pwm.EnsureStarted(kb::Milliseconds{20U}).IsOk()) {
  static_cast<void>(kb::handlers::pca9685::SetPwmFrequency(pwm, 50U, kb::Milliseconds{10U}));
  static_cast<void>(kb::handlers::pca9685::SetPulseWidthUs(pwm, 0U, 1500U, kb::Milliseconds{5U}));
}
```

Tests: `tests/integration/pca9685/` (the driver's register model behind a `kb::iface::I2cBus`, its time on the RTOS
clock, OE behind a host GPIO fake, both thread models).

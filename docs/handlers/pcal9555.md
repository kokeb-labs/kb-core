# pcal9555 handler

PCA9555 and PCAL9555A 16-bit I2C GPIO expanders, through `kb::handlers::pcal9555::Handler<Bus>`
(`kb/handlers/bindings/pcal9555.hpp`, driver `driver-pcal9555` at the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `inputs` (input port levels), `outputs` (the levels the driver last set), `interrupts` (pins whose interrupt status was seen) |
| Command | `WriteOutputs(io, high_mask, timeout)` | Every output: mask bits high, the others low |
| Command | `SetOutputs(io, mask, high, timeout)` | The outputs in `mask` high or low |
| Command | `ReadInputs(io, timeout)` | The input ports, read now |
| Command | `Command{Op::...}` with `Request()` | Toggle, pulls, input latch, output mode, interrupt status, reset check |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus.

## Thread model

`kRequiresOwner = false`. An expander is slow and used from several tasks, so a guarded bus
(`BusDomain<Bus, ThreadModel::Guarded>` with `Guarded<Handler>`) is the usual choice; on an owner bus the owner task
samples the inputs every `sample_period` and other tasks read `Latest()`.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: presence, identity pattern, every register written and read back | `Config::start_deadline` |

The chip has no reset pin and no software reset, so there is no `HostReset` stage. On a failure the report names
stage 0 with the driver's error in `detail`; the next `EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `DeviceReset`, `NotInitialized` | `NotReady` | Faulted at once (the chip lost its registers) |
| `Bus` | `BusError` | Counts toward `fault_after` |
| `NoDevice` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `DeviceIdMismatch`, `WriteMismatch`, `DeviceFault` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `Unsupported`, `Timeout`, `Crc`, `Busy` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |

Recovery is the generic plan: `Deinitialize()`, then the start-up again, which writes the whole configuration.

## Example

```cpp
using Bus = board::I2c0;                                          // a kb::iface::I2cBus
using Io = kb::handlers::pcal9555::Handler<Bus>;
kb::handlers::BusDomain<Bus, kb::handlers::ThreadModel::Guarded> i2c0{bus};
kb::handlers::Guarded<Io, decltype(i2c0)> io{i2c0, bus, timing, config};

static_cast<void>(i2c0.Create());
static_cast<void>(io.Create());
if (io.EnsureStarted(kb::Milliseconds{20U}).IsOk()) {
  static_cast<void>(kb::handlers::pcal9555::WriteOutputs(io, 0x00FFU, kb::Milliseconds{5U}));
  const kb::Result<uint16_t> in = kb::handlers::pcal9555::ReadInputs(io, kb::Milliseconds{5U});
}
```

Tests: `tests/integration/pcal9555/` (the driver's protocol model behind a `kb::iface::I2cBus`, both thread models).

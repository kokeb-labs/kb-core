# at25040b handler

AT25010B, AT25020B and AT25040B SPI serial EEPROMs (128 to 512 bytes, 8-byte pages), through
`kb::handlers::at25040b::Handler<Dev>` (`kb/handlers/bindings/at25040b.hpp`, driver `driver-at25040b` at the pin in
`components/drivers/drivers.lock.yml`). The chip is one `kb::iface::SpiDevice` (its chip select).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | none | A memory has nothing to sample (`Sample()` is `Unsupported`) |
| Command | `Read(io, address, out, timeout, verify)` | `out.size()` bytes from `address`; `Verify::ReadBack` reads each chunk twice |
| Command | `Write(io, address, data, timeout)` | `data` to `address`; the driver splits pages and waits each write cycle |
| Command | `ReadStatus(io, timeout)` | The status register (raw byte, write enable latch, BP1:BP0) |
| Command | `GetBlockProtection(io, timeout)` / `SetBlockProtection(io, level, timeout)` | BP1:BP0 |

A request moves at most `kChunkBytes` (16) bytes. `Read()` and `Write()` split a longer range into one request per
chunk, all within the one `timeout`; a failed chunk ends the call with the chunks before it done. Between chunks
another task's call may run; to keep a range (or a record written in several calls) whole, run it held
([bus access](../design/bus-access.md)): `auto held = rom.Hold(timeout); at25040b::Write(held, ...);` on a guarded
bus, `rom.Held(bus_hold)` on the owner task of an owner bus. The optional WP
pin is `Config::write_protect` (active low: asserted = pin low = writes blocked; absent: WP tied high).

## Thread model

`kRequiresOwner = false`. An EEPROM is slow and used now and then from several tasks, so a guarded bus is the
usual choice. On an owner bus requests go through the owner task's queue; there is no periodic sample.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: configuration check, WP parked, the idle status read until a pending write cycle ends and read again, the write enable latch toggled (or the first bytes read twice) | `Config::start_deadline` |

The chip has no reset or enable pin, so there is no `Power` or `HostReset` stage. A floating MISO (no chip) fails
stage 0 with `NoDevice`; a chip that answers unlike an AT25xxxB with `Fault` (`DeviceIdMismatch`).

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `NotInitialized` | `NotReady` | Faulted at once |
| `Bus`, `BusNoise`, `Pin` (WP could not be driven) | `BusError` | Counts toward `fault_after` |
| `NoDevice` | `NoDevice` | Counts toward `fault_after`; at start-up the start fails |
| `Timeout` (a write cycle that never ends) | `Timeout` | Counts toward `fault_after` |
| `DeviceIdMismatch`, `WriteProtected`, `WriteMismatch`, `DeviceFault` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `BlockProtected` | `InvalidArgument` | Refused: recorded as the last error, not counted against the chip (a caller's mistake) |
| `Unsupported`, `Crc`, `Busy` | the same name | Counts toward `fault_after` |

Recovery is the generic plan: `Deinitialize()` (WRDI, WP parked), then the start-up again.

## Example

```cpp
using Dev = board::EepromCs;                                      // a kb::iface::SpiDevice
using Io = kb::handlers::at25040b::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Guarded> spi2{dev};
kb::handlers::Guarded<Io, decltype(spi2)> rom{spi2, dev, timing, config};

static_cast<void>(spi2.Create());
static_cast<void>(rom.Create());
std::array<uint8_t, 32> blob{};
if (rom.EnsureStarted(kb::Milliseconds{20U}).IsOk()) {
  static_cast<void>(kb::handlers::at25040b::Read(rom, 0x0100U, blob, kb::Milliseconds{20U}));
}
```

Tests: `tests/integration/at25040b/` (the driver's chip model behind a `kb::iface::SpiDevice`, its write cycles on
the RTOS clock, WP behind a host GPIO fake, both thread models).

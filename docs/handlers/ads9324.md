# ads9324 handler

ADS9324 16-channel simultaneous-sampling ADC on SPI, through `kb::handlers::ads9324::Handler<Dev>`
(`kb/handlers/bindings/ads9324.hpp`, driver `driver-ads9324` at the pin in `components/drivers/drivers.lock.yml`).

## What it gives the application

| Kind | Name | What |
| --- | --- | --- |
| Snapshot | `Snapshot` | `microvolts[16]`, `codes[16]`, `present_mask`, `clipped_mask`, `window_alert`, `standby` |
| Command | `Identify(io, timeout)` | DEVICE_ID, read now (0x0004) |
| Command | `ReadWindowFlags(io, timeout)` | The latched window comparator flags of both banks |
| Command | `ClearWindowFlags(io, group, timeout)` | Clears the flags of group 0 (AIN1 to AIN8) or 1 (AIN9 to AIN16) |
| Command | `SetStandby(io, standby, timeout)` | Power down, or wake and check the registers |
| Command | `RunCalibration(io, timeout)` | The ADC calibration configured in `chip.calibration` |
| Command | `RunSelfTest(io, timeout)` | Test patterns on every channel; the configuration is restored |
| Command | `Command{Op::...}` with `Request()` | Reset (software or RESET pin), CONVST pulse, alarm pin, calibration off, raw register |

`io` is either facade; the calls are the same on an owner bus and on a guarded bus.

**Pins.** `Config::outputs` holds RESET (`kPinReset`, wire it active low) and CONVST (`kPinConvst`, active
high); `Config::inputs` holds DRDY/ALARM (`kPinAlarm`) at its electrical level: leave `active_low` false,
the driver applies `Alarm::active_low` itself. An absent pin makes the driver's pin calls fail (`Bus`): wire
CONVST, or set `host_convst = false` when the board drives CONVST and `Measure()` should wait for data
ready and read the frame. `CaptureLanes` has no kb contract, so data comes on SDOUT (one lane).

**Samples.** `Measure()` is `MeasureOnce()` (CONVST pulse, data-ready wait, frame read) or, with
`host_convst = false`, `WaitDataReady()` then `ReadFrame()`. While the chip is powered down it sends
nothing and republishes the last frame with `standby` set, so an owner task does not count standby as
failures.

The port's `DelayUs` goes through the hook timing: a spin on the HAL's busy-wait below 1 ms, a
`kb::rtos::SleepFor` (at least the time asked) from 1 ms.

## Thread model

`kRequiresOwner = false`. A converter sampled at the control period is the owner model's case: the owner
task converts every `sample_period` and every other task reads `Latest()` without a lock, with the sequence
and age of the frame. A guarded bus works for occasional reads from several tasks.

## Start-up

| Stage | Kinds | Mode | Driver call | Deadline |
| --- | --- | --- | --- | --- |
| 0 | `Identify + Configure` | sync | `EnsureInitialized()`: 30 ms power-up wait, reset (RESET pin with `chip.hardware_reset`, else SW_RST), DEVICE_ID and BANK_SEL, calibration idle, configuration written, optional calibration | `Config::start_deadline` |

The driver drives RESET itself, so there is no `HostReset` stage. On a failure the report names stage 0
with the driver's error in `detail`; the next `EnsureStarted()` starts again.

## Health

| Driver error | kb::Status | Effect |
| --- | --- | --- |
| `UnexpectedReset`, `NotInitialized` | `NotReady` | Faulted at once (RESET_DETECT_FLAG: the registers were lost) |
| `Refused` | `NotReady` | Counts toward `fault_after` (a call the powered-down chip refuses) |
| `Bus`, `DataMismatch` | `BusError` | Counts toward `fault_after` (a failed transfer, or a stuck or floating SDOUT frame) |
| `DeviceIdMismatch`, `DeviceFault`, `VerifyFailed` | `Fault` | Counts toward `fault_after` |
| `InvalidArgument`, `Timeout`, `Busy`, `Unsupported` | the same name | `InvalidArgument` is refused (recorded, not counted); the others count toward `fault_after` |
| `Crc` | `CrcMismatch` | Not returned by the driver |

Recovery is the generic plan: `Deinitialize()` (standby), then the start-up again, which resets the chip
and writes the whole configuration.

## Example

```cpp
using Dev = board::Spi2Adc;                                       // a kb::iface::SpiDevice, mode 0
using Adc = kb::handlers::ads9324::Handler<Dev>;
kb::handlers::BusDomain<Dev, kb::handlers::ThreadModel::Owner> spi2{dev};
kb::handlers::ads9324::Config config{};
config.outputs[kb::handlers::ads9324::kPinConvst].pin.emplace(convst_pin);
config.handler.sample_period = kb::Milliseconds{10U};
kb::handlers::OwnerAccess<Adc, decltype(spi2)> adc{spi2, dev, timing, config};

static_cast<void>(adc.Create());
adc.RequestStart();                                              // the owner task runs the plan
// owner task, every step: static_cast<void>(spi2.Service(kb::rtos::Now(), adc));
const auto frame = adc.Latest();                                 // any task, lock-free
```

Tests: `tests/integration/ads9324/` (the driver's chip model behind a `kb::iface::SpiDevice` and kb GPIO
pins, both thread models).
